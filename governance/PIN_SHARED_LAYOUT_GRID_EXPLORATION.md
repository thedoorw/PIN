# PIN 共用排版規律研究 — 暫定範例（2026-10-16）

**狀態：USER 提供的候選分配，僅記錄、不代表定案或已實作。**

## 目的

建立 PIN 網頁各模組共用的排版邏輯，避免照片牆、研究表格等功能各自拼湊尺寸、反覆修補版面，影響 PIN 與 INK 的轉譯測試進度。

## 候選範例：1280px 視窗、四欄縮圖

| 構成 | 數值 |
| --- | ---: |
| 左側總留白 | 64px |
| 單一縮圖框寬 | 276px |
| 相鄰縮圖框間距 | 16px |
| 縮圖框數 | 4 |
| 右側總留白 | 64px |
| 合計視窗寬 | 1280px |

驗算：`64 + (276 × 4) + (16 × 3) + 64 = 1280`。

這是**以 16px 作為模矩探索起點**得到的一種完整寬度分配，**不是固定尺寸規格**。左右留白與框距在這個範例中是 16 的整數倍；**276px 是按總寬、留白、欄數及間距推算的結果，不是 16px 的整數倍**，不應誤寫為所有尺寸均需是 16 的倍數。

## 待研究的整體規律（尚未定案）

- 建立統一的水平配置關係：`視窗寬度 W = 2 × 左右總留白 M + 欄數 N × 卡片寬 C + (N - 1) × 欄距 G`。左右留白對稱；`C = [W - 2M - (N - 1)G] / N`。如依實際可用寬度計算，必須先一致處理捲軸佔用。
- **左右「總留白」必須包含捲軸／預留 gutter 所佔的份額**，不能把瀏覽器內容區置中誤當成整個視窗的視覺置中。實際 gutter 寬由瀏覽器決定，無須預設為 15px。
- 研究 16px 模矩的用途、縮圖與容器寬度如何自適應、在哪些視窗寬度或斷點更換欄數，避免只針對 1280px 強配固定數字。
- 照片牆現階段以**桌面四欄**為基線，不引入五欄；其餘響應式配置須與整體模矩一起驗證。
- 照片牆、研究文件表格、頁首導覽與後續模組應共用容器邊界與置中規則，但不必強制共用相同欄數。
- **驗證優先於調參**：至少以不同視窗寬度檢查總寬守恆、左右視覺留白、欄距與縮圖尺寸；需實際瀏覽器驗收，不可以原始碼檢查代替畫面驗收。
