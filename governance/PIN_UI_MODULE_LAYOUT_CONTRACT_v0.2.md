# PIN UI 共用排版與模組界線 v0.2

狀態：**模組結構基準／首輪實作中**；依 USER 2026-10-20 對話接續 v0.1。G0 與 01～03 已部署且獲 USER 視覺確認，**00 頂部導覽列 2026-10-20 原版已經 USER 指定三項驗收通過；2026-10-22 全視窗兩端 48px 新版需另外驗收**。原始檢查範圍：`index.html`、`styles/base.css`、`styles/gallery.css`、`styles/research-sheet.css`、`styles/settings.css`、`app.js`，以 GitHub `thedoorw/PIN/main` 為準。

## 1. 核心目標

將 PIN 既有頁面由上而下切分，先定義每個模組的**用途、寬度責任、共用基準線、垂直間距責任、切換／捲動邊界**，讓之後增加導覽列或其他內容時不再局部猜像素。減少 PIN 介面反覆修補對 INK 轉譯測試造成的阻礙。

**一個排版規則只有一個擁有者。先規律、再數值；先結構、再功能。**

## 3. 頁面外框 PageShell：所有模組共用一套

- **G0 PageShell** 不是一個顯示區塊，而是 01、02、03 三個內容模組必須遵守的**共同幾何外框**；00 TopNav 因 USER 2026-10-22 的工具間識別一致性需求，明確獨立採整個 viewport 的左右邊緣。
- 唯一擁有：視窗／捲軸 gutter、最大容器寬度、左右留白、RWD 切換規則、全頁共同對齊座標。
- 定義兩條直線：`L = 共用內容左緣`、`R = 共用內容右緣`。**01／02／03 模組外框**遵守 `left=L` 與 `right=R`；**01 標頭的左側文字另有 16px 內縮**。00 的最外側 LOGO 與設定控制區沿 viewport 邊界配置，**不再套用 G0 padding、max-width 或 L/R**。
- **使用整個視窗作為置中基準**，左右「總留白」各自計入瀏覽器捲軸與預留 gutter。捲軸寬由瀏覽器決定，**不得**在一般規則中假定它永遠是 15px。
- 00 TopNav **背景與內部控制位置都採全視窗**；48×48 LOGO 方框左緣在 viewport x=0，48×48 設定方框右緣在 viewport 最右側，搜尋方框緊鄰設定左側。需考慮 `scrollbar-gutter:stable both-edges` 且避免 body 水平溢出；此例外**不改 G0 或 01～03**。
- Header、Nav、Gallery、Research 不再分別定義獨立的左右位移／中心線，也不靠負 margin 或絕對定位補正其他模組的寬度。
- **禁止新增一組似是而非的固定寬度**；可依視窗／容器尺寸推算，但必須與此坐標契約一致。

**USER 2026-10-20 補充並已實作：** 在所有視窗寬度下，01 標頭的 PIN 名稱及左側文字起點應比 03 主內容（照片牆第一框／研究表格外框）的左邊界**向內 16px**。這是一條額外的視覺層級規則，不取消 00～03 模組外框共用 L/R；標頭右側搜尋與設定保持靠 R。00 頂部導覽列、02 分類導覽、03 內容不套用此內縮；相關樣式已實作於 `styles/base.css`。

### 3.1 暫定 16px 模矩研究不變

使用者已提出一個**例子而非定案**：

`1280 = 64 + 4 × 276 + 3 × 16 + 64` （完整視窗寬；左右總留白各 64px；四欄；欄距 16px）

- 16px 是模矩研究出發點，**不要求每個結果是 16px 整數倍**；縮圖 276px 是推算所得。
- 固定的應是**欄數、間距 token、容器邊界及計算規則**，不是把某張截圖的尺寸硬套到各種視窗。
- 一般式：`W = 2M + N×C + (N−1)×G`；`C = (W−2M−(N−1)G)/N`，其中 W 為完整視窗、M 為含 gutter 的單側總留白、N 為欄數、G 為框距。
- Gallery 桌面**四欄**，不建立五欄。先不變更目前響應式斷點，斷點要依實際容器寬、內容最小可讀性與視覺驗收再定。
- 照片牆與研究表格可以有不同的**內部欄位**，但不能有不同的**外部頁面留白**。

## 4. 模組間的垂直分配及責任

定義垂直流向：

`00 TopNav（48px） → 01 Header → 02 CategoryNav → 03 MainContent`

- **區段間距**屬於 PageShell／共用 Layout 層，不得由上區的 margin 與下區的 padding 分別加總出無意義的空白。
- 建議以 16px 模矩為尺度，研究 `8 / 16 / 24 / 32px` 的間距階梯；這組間距階梯亦是**候選**，不是已核准的最終 UI。
- Header 高度由標題與自訂文字的實際內容決定；搜尋與設定已移入 00；**01 不強制固定高度**。
- CategoryNav 現有 `position: sticky; top:0`。00 本輪採**正常文流、不固定**，因此 02 保持 `top:0`。未來如把 00 改為 sticky/fixed，02 offset 需要另行核對，禁止互相遮擋。
- **02 → 03 的 Y 間距必須共用**，不可沿用 Gallery 13px、Research 6px 各算一套。切換分類或研究文件時，03 的左緣、右緣、上緣不應漂移。
- 03A Gallery：卡片本身不影響 Nav 起點、頁面邊界；追加載入按鈕視為 Gallery 子項。
- 03B Research：工具列、Google 登入區、表格與說明文字均是 Research 內部層級；五欄或以後新增欄位的數量由私人 Google Sheets 現況決定，並非由 layout 規格決定。真正超寬時才水平捲動；縱向由整頁捲動。
- Settings 面板仍可獨立捲動、以控制按鈕作 anchor；打開浮層**不得推開 00–03**，也不得造成全頁水平捲動。

## 5. 模組所有權（避免新一輪拼湊）

| 應由誰決定 | 範圍 | 不可做的事 |
| --- | --- | --- |
| **G0 共用 Layout／tokens** | 01～03 的左右 L/R、gutter、最大寬、主模組垂直間隔、RWD 準則 | 不讓個別內容模組透過自行左右 padding／margin 改寫外框；00 是明確例外 |
| **00 TopNav（已實作，新版待驗收）** | 視窗全幅、48px 高度、48×48 LOGO 與搜尋／設定固定控制區、可自訂 LOGO | 不再繼承 G0 內縮；不更動 01～03、02 分類或私人研究資料 |
| **01 Header** | PIN 標題、caption，文字從 L+16px 起 | 搜尋／設定只存在於 00，不重複製作；不能連帶平移整個模組 |
| **02 CategoryNav** | 五種分類切換、按鈕間距、sticky 行為 | 不負責 03A 或 03B 的外框／起始 Y |
| **03A Gallery** | 桌面四欄、縮圖 3:2、卡片內部資訊、框距 | 不修改 PageShell 的左右留白 |
| **03B Research** | 工具列、表格欄位、欄寬／列高、Sheets 同步 | 不擅自補回已刪除的欄位、不用固定寬撐開頁面 |
| **現有 Settings 浮層** | 搜尋／設定觸發後之面板位置與內部排列 | 不假裝已存在獨立通用的 M04，亦不干涉主文流 |

「模組化」**首先是界線與所有權**，不是立刻拆更多 JS/CSS 檔案。正式重構應先讓樣式來源唯一化，再視需要拆 HTML 結構與行為模組。

## 10. 2026-10-22 USER TopNav 統一工具識別位置（新規則）

**USER 目的：** PIN 與 INK 的 LOGO 都固定在視窗最左上角的 **48×48px** 識別控制區。PIN 最右側設定與其左搜尋也為 **48×48px**，圖示／LOGO 水平、垂直置中，形成工具列左右兩端的鏡像控制座標。這不是把 LOGO 沿 Gallery L 再微調，而是 **00 的整個內層獨立於 G0**；下方標頭 L+16、分類及四欄 Gallery 須保持不動。

**實作界線：** 僅更動 `index.html` 中 00 容器 class／CSS cache identity 與 `styles/base.css` 的 TopNav 位置／尺寸及必要的手機斷點；既有搜尋、設定、LOGO 上傳／網址／本機保存及展開面板 JS ID 均不變。根 `scrollbar-gutter:stable both-edges` 與 01～03 的 G0 幾何保持不變。避免因 `100vw` 加大內容而引入水平溢出。

**驗收待核：** 桌面 1280、1920 與小尺寸 320px；TopNav LOGO `x=0,width=48,y=0,height=48`，搜尋 `right=W-48`，設定 `right=W`；打開搜尋時按鈕錨點固定，設定浮層正常展開／click-away／Escape；不應破壞 01～03 寬度、個人設定或新增水平捲軸。此處的 source/本機幾何測試與公開 Pages、USER 視覺驗收**必須分開記錄**。
